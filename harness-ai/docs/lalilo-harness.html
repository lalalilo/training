P1 — Concrete · TOP priority

PreToolUse deny-gate for prod / infra / secrets

# .claude/hooks/guard-dangerous-bash.sh  — wired as PreToolUse(Bash)
# exit 2 = block unconditionally (deterministic, model can't override)
cmd=$(jq -r '.tool_input.command')

# 1. Destructive DB / migrations
case "$cmd" in
  *"migrate down"*|*"DROP "*|*"TRUNCATE"*|*"DELETE FROM"*)
    echo '{"decision":"block","reason":"Destructive DB op — run manually with review"}'; exit 2 ;;
  # 2. Infra mutations: k8s + ArgoCD must be human-gated (Rule of Two)
  *"kubectl apply"*|*"kubectl delete"*|*"argocd app sync"*|*"helm upgrade"*)
    echo '{"decision":"block","reason":"Infra mutation — deploy is human-gated"}'; exit 2 ;;
  *"git push"*" main"*|*"git push"*" staging"*)
    echo '{"decision":"block","reason":"Never push protected branch"}'; exit 2 ;;
esac
exit 0  # everything else proceeds without a prompt → low friction

Pairs with secret-scan on Edit/Write (block writes containing key patterns) + keeping AWS OIDC short-lived creds in CI. No static secret on disk.

P2 — Concrete

Cross-app blast-radius guard in .husky/pre-commit 

#!/bin/sh
. "$(dirname "$0")/_/husky.sh"

yarn lint-staged

# NEW: reject commits that span more than one app (monorepo contamination)
apps=$(git diff --cached --name-only \
  | grep '^apps/' | cut -d/ -f2 | sort -u)
count=$(echo "$apps" | grep -c .)

if [ "$count" -gt 1 ]; then
  echo "✋ Staged changes span $count apps: $apps"
  echo "   Commit one app at a time (monorepo blast-radius guard)."
  echo "   Override: git commit --no-verify  (use deliberately)"
  exit 1
fi

Turns the CLAUDE.md instruction "stage only your app's files" into deterministic enforcement. Human can still override with --no-verify; the agent cannot silently sweep 7 apps.

P3 — Concrete

Verification-before-done — stop hook

# .claude/hooks/verify-before-stop.sh — Stop hook
app=$(cat .omc/state/active-app 2>/dev/null)
[ -z "$app" ] && exit 0

cd apps/"$app" || exit 0
yarn check-types >/dev/null 2>&1 \
  && yarn test:unit >/dev/null 2>&1 \
  || { echo '{"decision":"block",
    "reason":"types or unit tests fail — not done"}'
       exit 2; }

+ phrase guard

  • Block exit on "pre-existing", "known limitation", "should I continue"
  • test-author ≠ code-author for new features
  • Adversarial self-review subagent on the diff
  • Harness overrides after 8 blocks (anti-loop)

Re-port the 4-tier verify hook that the reference repo built then disabled — strongest false-done guard.

P4 — Concrete

Per-app architecture rules + fitness function

# .claude/rules/lalilo-api.md   (auto-loaded when touching apps/lalilo-api)
## Layered architecture — enforced
- routes/      → controllers + yup schemas only, NO business logic
- services/    → business logic, reusable
- data-layer/  → models/ (Sequelize) + queries/ (one file per model)
- policies/    → authz checks, called at start of controllers

## Hard rules
- NO Sequelize queries outside data-layer/queries/
- Each *.queries.ts MUST have a matching integration test
- Sub-routers require mergeParams: true
- Migrating Sequelize → Drizzle: new code prefers Drizzle

CI enforcement: yarn test:structure already exists → make it a required status check so an AI PR violating layer boundaries cannot merge. This is the architectural fitness function (ThoughtWorks Radar 34).

Sequencing

Ship the safety floor first

P1–P3 (deny-gate, cross-app guard, verify-before-done) are deterministic, high-value, low-risk — land them first and they pay off day one. P4–P6 add reuse + self-improvement. P7–P8 make not-reading-every-line defensible for real customers.

P1–P3 = safety floor P4–P6 = efficiency + self-improvement P7–P8 = ship-to-customer
